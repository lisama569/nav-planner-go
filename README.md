# nav-planner-go

本地可复现的导航与路径规划参考实现：用本地栅格地图与圆形障碍物模拟差速驱动移动
机器人的自主导航，使**全局路径、局部避障与重规划**在各入口（`Plan` /
`ReplanningStep` / 录制重放）下给出可解释且一致的结论。

核心保障：

- **入口一致的世界观**：一次性入口 `Plan` 与逐步推进入口 `ReplanningStep` 共用
  同一个“规划—终检—膨胀重规划”闭环，同一张地图、同一批已接受的动态障碍下，
  两边结论（成功/绕行/不可达/被拒绝）与路线可以互相解释；
- **交付轨迹整体终检**：任何 `PLANNED`/`REPLANNED` 结论在返回前，都把最终交付的
  整条轨迹对当前所有已知动态障碍复核一遍，撞障轨迹绝不下发；
- **可配置规划时限**：确定性展开预算兜底最坏耗时（默认），另可选配墙钟兜底时限，
  超时统一分类为可区分的 `PLAN_LIMIT`（超时/未完成类），绝不下发半成品。

无第三方依赖，仅使用 Go 标准库。

## 目录结构

| 包 | 职责 |
| --- | --- |
| `pkg/grid` | 二维占据栅格地图，固定邻居顺序，深拷贝快照 |
| `pkg/planner` | 确定性 A* 全局搜索与可区分错误分类 |
| `pkg/kinematics` | 差速驱动位姿/约束模型、路径→轨迹构造、轨迹校验 |
| `pkg/local` | 确定性动态窗口法（DWA）局部避障 |
| `pkg/nav` | 线程安全编排器：规划闭环、重规划、乱序更新治理 |
| `pkg/replay` | 事件录制与逐条比对的确定性重放 |
| `cmd/navdemo` | 端到端演示（正常→遇障绕行→封死不可达→非法输入→重放） |

## 规划与避障策略

### 1. 全局规划：确定性 A*（`pkg/planner`）

- 四邻域移动，代价均为 1；启发式为曼哈顿距离（在四邻域网格上可采纳且一致）。
- 开放表按 `(f, 插入序号)` 排序，邻居按 **上→右→下→左** 固定顺序展开，
  因此同地图、同起终点的平局裁决完全确定，跨进程逐位复现。
- 搜索受**展开预算** `maxExpansions` 约束（默认 1,000,000）。预算是确定性的
  “规划时限”：不使用墙上时钟（墙上时钟会引入机器负载相关的不确定性），
  超预算返回 `ErrPlanLimit`，由编排层标记为 `StatusPlanLimit`，绝不返回空轨迹
  冒充成功。

失败原因使用一组彼此可区分的哨兵错误（`errors.Is` 判定）：

| 错误 | 含义 | 编排层状态 |
| --- | --- | --- |
| `ErrMapMissing` | 地图缺失 | `REJECTED` |
| `ErrStartOutOfBounds` / `ErrGoalOutOfBounds` | 起点/终点越界 | `REJECTED` |
| `ErrStartOccupied` / `ErrGoalOccupied` | 起点/终点落在障碍上 | `REJECTED`（重规划中起点被封为 `BLOCKED`） |
| `ErrUnreachable` | 开放表耗尽仍到不了目标 | `UNREACHABLE` |
| `ErrPlanLimit` | 超出展开预算 | `PLAN_LIMIT` |

### 2. 轨迹构造与约束模型（`pkg/kinematics`）

机器人为差速驱动：指令是体坐标系 `(V, Omega)`，单段运动学按圆弧/直线
**精确积分**（`Integrate`）。栅格 `(x,y)` 的中心映射到世界坐标 `(x, y)`。

默认约束（`DefaultConstraints`）：

- 线速度 `0 ≤ V ≤ 1.0` 栅格/秒；
- 角速度 `|Omega| ≤ π/2` 弧度/秒；
- 曲率约束（仅行进段）`|Omega/V| ≤ 1.0`（1/栅格），保证最小转弯半径；
- 单段转角变化 `|Δθ| ≤ π/2`，角度差按最短方向包裹到 `[-π, π]`；
- 每段 `DT > 0`；
- **位姿连续**：每段必须能用其 `(V, Omega, DT)` 精确积分到下一个采样点
  （容差 `1e-7`），否则记 `ViolationDiscontinuity`。

`PathToTrajectory` 按构造即合法：每条网格边先“原地分段转向”（`V=0`、
`|Omega|=MaxOmega`、每段转角不超过 `MaxDTheta`），再以 `MaxV` 匀速直行，
末段精确落在下一个单元格中心。`nav` 层在下发前仍会调用 `Validate` 二次复核；
任何违规结论为 `StatusConstraintViolation`（`ErrConstraintViolation`），
违规轨迹**不会被当作有效结果下发**。

违规分类：`ViolationVelocity / ViolationAngularVelocity / ViolationCurvature
/ ViolationTurnAngle / ViolationDiscontinuity / ViolationTiming`，
每条违规带段号与可读信息。

### 3. 局部避障：确定性 DWA（`pkg/local`）

- 在动态窗口内**确定性枚举** `(V, Omega)`：线速度从高到低、角速度从
  `-OmegaMax` 到 `+OmegaMax`（对称采样），固定枚举顺序就是固定平局裁决。
- `OmegaMax` 同时受 `MaxOmega` 与 `MaxDTheta/DT` 收紧；行进段还要满足曲率上限。
- 候选指令用差速运动学精确前滚 `Horizon` 步，任一点进入圆形障碍
  （半径 + `ObstacleMargin` 安全裕度）或越界/占据栅格即淘汰。
- 采用**胡萝卜点跟随**：沿全局路径在前视半径内选最远可达的路径单元格作为
  瞄准点（前视半径至少一个栅格），避免斜切墙角与原地摇摆。
- 评分 = 末端到目标距离 + 朝向偏差权重 − 间隙裕度权重，仅在严格更优时替换，
  保证平局可复现。停车指令 `(0,0)` 不参与寻优，防止“原地不动”被误判为最优
  而永久停滞；原地转向 `(0, Omega≠0)` 保留用于对正。
- 除停车外没有任何合法候选时返回 `blocked=true`，由编排层触发重规划。

### 4. 统一规划闭环：入口一致性、交付终检与重规划（`pkg/nav`）

`Plan`（一次性要完整路线）与 `ReplanningStep`（按执行过程逐段推进）共用同一个
闭环 `planLoop`，区别仅在于 `ReplanningStep` 额外做 DWA 局部可执行性验证：

1. 深拷贝当前地图快照作为工作地图（不污染已装载地图）；
2. 全局 A* → 构造轨迹 → 运动学约束校验；
3. **交付轨迹整体终检**：把最终要下发的整条轨迹，对**当前所有已知动态障碍**
   （含安全裕度）与真实地图逐点复核（`local.Planner.CollidesAt`/`Collides`）。
   一旦发现冲突——包括“栅格路径合法、但连续轨迹擦碰障碍”的情形——
   把冲突单元格与障碍足迹（含安全裕度、按 `(Y,X)` 排序去重）确定性膨胀进
   工作地图，回到第 2 步；
4. 仅 `ReplanningStep`：再用 DWA 沿路径短步推进做“可执行性”验证，
   局部窗口被堵时同样膨胀重规划；
5. 成功时若是绕行得到的结果，状态为 `REPLANNED`（否则 `PLANNED`）；
   重规划后目标不可达为 `UNREACHABLE`；预算/时限耗尽为 `PLAN_LIMIT`；
   机器人被封死或超过 `maxReplans=4` 次仍撞障为 `BLOCKED`。

由此得到的一致性保证：

- **同一世界状态、同一请求下，两个入口把同一批已接受的动态障碍算进世界观**，
  不会出现“一个入口说能走、路线却穿过已知障碍”的对不上情况；
- 动态障碍膨胀导致目标被覆盖时，两个入口都分类为 `UNREACHABLE`
  （原因含 `planner.ErrUnreachable`）；起点被动态障碍封死时都为 `BLOCKED`，
  与“目标本身非法”（`REJECTED`）可区分；
- 任何失败/超时结论都不携带路径与轨迹（半成品绝不下发）；
- 语义差异仅剩一处且可解释：`ReplanningStep` 额外验证 DWA 可执行性，
  因此它可能在 `Plan` 接受的个别场景下多触发一次绕行重规划。

### 5. 规划时限：确定性预算 + 可选墙钟兜底

两层“超时/未完成”保护，结论统一分类为 `StatusPlanLimit`：

| 机制 | 配置 | 性质 | 触发后的原因 |
| --- | --- | --- | --- |
| 展开预算（默认 1,000,000） | `planner.New(maxExpansions)` | **确定性**：同输入必同结论，与机器负载无关 | `planner.ErrPlanLimit` |
| 墙钟兜底时限（默认禁用） | `nav.Navigator.SetOptions(nav.Options{PlanTimeout: d})` | 实时兜底：兜住超大/极端地图的最坏耗时 | `nav.ErrPlanTimeout` |

边界与取舍（工程判断）：

- **默认完全确定性**：`PlanTimeout<=0` 时不读任何墙上时钟，重放/复现保证不变；
  单次 A* 的最坏耗时由展开预算界定，重规划次数由 `maxReplans` 界定，
  局部推进由 `MaxIters` 界定，因此总耗时本身有界。
- **启用墙钟兜底后**，超时是否在边界负载下触发与机器有关，跨机器重放可能在该点
  分叉——这是用“实时兜底”换“严格复现”的显式权衡；但无论何时触发，结论都
  明确是 `PLAN_LIMIT` + `ErrPlanTimeout`，且不下发任何路径/轨迹，
  绝不会把半成品当有效结果。
- 兜底在每次规划尝试边界与局部推进迭代处检查；单次 A* 内部不中断
  （其耗时已由展开预算确定性地界定）。
- 超时只是放弃本次请求，不污染编排器状态；`SetOptions(nav.Options{})` 恢复默认后，
  同一输入立即回到确定性结论。

## 并发模型与确定性保证

- `Navigator` 用一把 `sync.RWMutex` 保护地图、障碍物表与序号水位；
  CPU 密集的规划在锁外基于**深拷贝快照**执行，既不阻塞传感器更新，
  也保证一次规划看到的是一致状态（`go test -race` 验证无数据竞争）。
- **乱序/陈旧更新规则**：
  - 地图更新按全局 `Seq` 单调，落后水位的更新被拒绝并返回
    `nav.ErrStaleUpdate`；`nil` 地图返回 `ErrInvalidUpdate`。
  - 障碍物更新按 `(障碍物ID, Seq)` 每 ID 独立水位判定：同一 ID 的旧观测被丢弃，
    不同 ID 的消息之间不要求全局排序——多个传感器可并发写不同 ID。
- `Snapshot()` 返回深拷贝地图与**按 ID 排序**的障碍物切片，保证读结果确定。
- 确定性来源：无 goroutine 参与决策、默认不读墙上时钟（见“规划时限”一节的
  墙钟兜底边界）、无 map 遍历顺序泄漏、固定枚举/展开/排序规则、浮点运算顺序
  固定。相同初始位姿、地图与障碍物序列在任意时间重放都得到逐位相同的路径与轨迹。
- `pkg/replay` 把事件（地图/障碍物/请求，按逻辑 Tick 排序）与结论录制成日志，
  可用全新 `Navigator` 重放并逐字段（状态、错误原因、重规划次数、路径、
  每个轨迹点）比对；比较采用**精确相等**而非近似，避免容差掩盖真实的不确定性。

## 验证方法

```bash
# 构建
go build ./...

# 全部单测（带竞态检测；测试日志打印输入状态、规划结果与判定依据）
go test -race -count=1 -v ./...

# 端到端演示
go run ./cmd/navdemo
```

测试覆盖的关键场景：

- **入口一致性**：同一世界状态（同地图+同批已接受障碍）下，`Plan` 与
  `ReplanningStep` 在绕行、封死不可达、非法输入三类场景给出一致且可互相解释的
  结论与路线（`TestEntryConsistency`）；
- **交付轨迹终检**：构造“栅格路径全自由、连续轨迹却擦碰障碍”的陷阱场景，
  终检必须发现并重规划，成功结论的轨迹逐一复核无碰撞，失败结论不携带路径/轨迹
  （`TestFinalTrajectoryRecheck`）；
- **超时分类**：极小兜底时限下两个入口都给出 `PLAN_LIMIT` + `ErrPlanTimeout`
  且无半成品；禁用兜底恢复确定性；充裕时限不改变正常结论；超时后状态不被污染
  （`TestPlanTimeoutClassified` / `TestTimeoutDoesNotCorruptState`）；
- **动态障碍**：障碍堵住近路缺口 → 障碍膨胀 → 重规划走低路
  （`REPLANNED`，路径不再经过被堵缺口）；
- **不可达目标**：两个缺口都被封死后 `UNREACHABLE` + `planner.ErrUnreachable`；
- **非法输入可区分**：目标越界、目标占据、起点占据、地图缺失、预算耗尽
  分别给出不同哨兵错误与状态分类；
- **约束违规**：超速、超角速度、超曲率、超转角、位姿不连续、非正 `DT`、
  空轨迹均被 `Validate` 标记；
- **并发更新**：多传感器并发写 + 并发快照/规划 + 并发乱序注入，`-race` 无报警、
  快照一致、乱序全部按水位拒绝；
- **确定性**：同输入多次运行结果逐位相同；录制/重放一致，且能检测出地图被
  篡改导致的分叉。

## 兼容范围

本次新增能力对既有用法保持向后兼容：

- `nav.New` / `Plan` / `ReplanningStep` / `ApplyMap` / `ApplyObstacle` / `Snapshot`
  的签名与并发/乱序语义不变；`SetOptions` 为纯新增，零值即旧行为；
- 默认配置（未调用 `SetOptions`）下不读墙上时钟，确定性重放保证不变，
  既有录制日志在新版本上重放结论一致；
- 状态枚举与哨兵错误只增不改：新增 `nav.ErrPlanTimeout`（归入既有
  `StatusPlanLimit` 分类），其余状态/错误语义不变；
- 行为收紧仅有两处，均属“旧行为本就不安全”的修复：`Plan` 现在会把已接受的
  动态障碍计入世界观（不再对障碍视而不见），且任何失败/超时结论不再携带
  路径与轨迹。
