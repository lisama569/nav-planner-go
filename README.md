# nav-planner-go

本地可复现的二维导航与路径规划库（Go）。用本地栅格地图与轴对齐障碍物
模拟差速/独轮式移动机器人的自主导航，在**全局规划、局部避障、动态重规划**
三类入口上给出**可解释且相互一致**的结论：所有失败都带可区分的分类码，
绝不返回空轨迹或静默成功；无效轨迹会被显式标记，不允许下发。

## 1. 总体结构

```
nav/
  errors.go       失败分类码（FailCode）与 PlanningError
  types.go        Pose/Cell/Obstacle/Config/Path/Trajectory/PlanResult
  clock.go        Clock 抽象、WallClock、FakeClock、StepClock
  grid.go         栅格地图、坐标变换、障碍栅格化、克隆
  planner.go      全局 A* 搜索（八邻域、贴角保护、确定性平局）
  trajectory.go   运动学轨迹生成与全约束校验
  local.go        局部避障（前瞻走廊冲突检查）
  navigator.go    并发编排：地图/障碍版本、序号去旧、规划落库
cmd/navdemo/      端到端演示：规划→侵入→重规划→合围不可达→移除恢复
```

典型调用：

```go
n, _ := nav.NewNavigator(cfg, nav.NewFakeClock(t0)) // 注入时钟
n.SetMap(nav.NewGridMap(cfg.Grid), staticObstacles) // 安装地图
n.ApplyObstacle(dynObstacle)                        // 传感器更新（带 Seq）
r := n.Plan(start, goal)                            // 规划/重规划
if !r.Succeeded() { /* r.Err.Code 区分原因 */ }
// r.Traj.Valid() == true 才允许下发执行
```

## 2. 规划与避障策略

### 2.1 全局规划（planner.go）

- 八邻域 A*，正交步代价 1、对角步代价 √2；启发函数为与移动模型一致的
  octile distance（可采纳，保证最优）。
- **贴角保护**：对角移动要求两侧正交邻格均自由，防止机器人贴墙角穿越。
- 越界栅格一律视为占据，搜索本身无需特判越界。
- 每次规划都基于“基础地图克隆 + 最新动态障碍栅格化”得到的**不可变工作副本**，
  因此全局搜索与局部检查使用的是同一张世界表示，结论一致。

### 2.2 重规划触发（navigator.go + local.go）

1. 传感器推送障碍更新（带 `Seq`），世界版本 `Seq++`；
2. 下一次 `Plan` 时，对**正在执行的旧轨迹**做局部冲突检查；
3. 若机器人当前位姿前方的前瞻走廊被侵入，则置 `Replanned=true`，
   `ReplanReason` 记录“触发证据（冲突点/栅格/弧长/障碍数）+ 重规划所用世界版本”；
4. 在新工作副本上重新执行 A* 与轨迹生成。新轨迹与障碍在同一世界副本上，
   从构造上保证无碰撞，并再做一次局部自检作为证据。

局部检查只评估机器人**前方** `LocalLookahead` 米的走廊：先按轨迹点与
当前位姿的距离跳过已驶过的历史段，身后障碍不会触发重规划。前瞻窗内
一旦出现冲突即判定需要重规划——冲突点之后即使存在自由栅格，也只是旧
轨迹几何上的点，不能保证机器人能连续无碰撞地到达，因此不会据此静默放行。

### 2.3 失败分类（绝不静默）

所有失败返回非 nil 的 `*PlanningError`，`Code` 可程序区分：

| Code | 触发情形 |
|---|---|
| `map_missing` | 地图缺失或栅格配置非法 |
| `not_initialized` | 未 `SetMap` 就调用 `Plan` |
| `start_invalid` | 起点 NaN / 越界 / 落入障碍 |
| `goal_invalid` | 目标 NaN / 越界 / 落入障碍 / 容差配置非法 |
| `goal_unreachable` | 开放集耗尽（合围）或新障碍使走廊封闭 |
| `obstacle_invalid` | 障碍几何非法（负半宽等）、空 ID |
| `planning_timeout` | 搜索或轨迹生成超过时限 |
| `constraint_violation` | 轨迹违反任一运动学/速度约束 |
| `stale_update` | 障碍更新序号陈旧或重复，被丢弃 |

目标不可达、起终点非法等情况不会返回空路径，轨迹超时/违规会以
`TrajStatus`（`TrajTimeout` / `TrajConstraintViolation` / `TrajBlocked`）
标记，`Trajectory.Valid()` 为 false，调用方不能下发。

## 3. 运动学与速度约束模型（trajectory.go）

差速/独轮模型，固定离散步长 `DT`：

```
x'     = x + v·cos(θ)·DT
y'     = y + v·sin(θ)·DT
θ'     = θ + ω·DT
```

**指令约定**：轨迹点 i 记录的 `(v,ω)` 是作用于区间 `[i-1, i]` 的指令；
点 0 的指令为零（真实初始状态）。因此相邻点位姿必须能由上一点位姿 +
当前点指令精确积分复现（1e-6 容差），这保证了连续执行中的位姿连续。

生成策略为“**原地转向对齐 → 梯形速度直行 → 末端对齐目标航向**”：

- 每个平移段先原地转向（v=0），单步角速度同时受
  `min(MaxAngularVel, MaxSteerRate/DT)` 与单步航向变化 `MaxStepTheta` 限制，
  最后一小步不越过目标航向；
- 平移速度曲线按最少步数 N 构造双向加速度受限的最大速度序列
  `w_i = min(Vmax, i·Δv, (N+1-i)·Δv)`（`Δv=MaxAccel·DT`），
  再整体等比缩放 `f = 段长/Σ(w_i·DT)`。缩放后：
  - 总位移**精确等于**段长（每段精确到达路径节点，最终精确到达目标）；
  - 相邻指令速度差 ≤ Δv，自动满足 `MaxAccel`；
  - 从 0 起步、到节点归 0，末端再追加零指令点表示真正停稳；
- 平移段 ω=0，曲率恒为 0，天然满足 `MaxCurvature`；校验器仍会对
  `|ω/v|` 做通用检查，约束模型不依赖生成器的实现细节。

`Validate` 是独立入口，对任意轨迹检查：NaN、速度上下限
（`MinLinearVel..MaxLinearVel`，支持倒车下限）、角速度/转向速率、
相邻点加速度、单步航向变化、曲率、时间步等距、以及位姿积分连续性，
并返回**第一条违规的人类可读原因**。

**时限**：生成器每产生一个点都检查注入时钟与 deadline；超时立即停止，
返回只含部分点、`Status=TrajTimeout` 的轨迹——部分轨迹不到达目标，
`Valid()` 为 false，不会被下发。

## 4. 并发模型与确定性保证（navigator.go）

### 4.1 并发一致性

- 一把 `sync.Mutex` 保护全部可变状态（基础地图引用、动态障碍表、
  每 ID 已见序号、世界版本 `Seq`、最近结果）。
- `Plan` 只在锁内做廉价的“克隆地图 + 拷贝障碍表”，随即释放锁执行
  耗时的 A* 与轨迹生成；结果落库前重新取锁并深拷贝
  （`cloneResult`），调用方拿到的切片与内部状态无别名共享。
- 这保证并发的传感器写入、规划、状态读取无数据竞争（已用
  `go test -race` 反复验证），且任何外部可见状态都是一致快照。

### 4.2 陈旧 / 乱序更新规则

动态障碍按 `(ID, Seq)` 处理：

- `Seq` 小于该 ID 已见最大序号 → 丢弃，原因码 `stale_update`
  （迟到的旧位置永远不能覆盖新位置，也不能复活已移除的障碍）；
- `Seq` 相等 → 幂等忽略；
- `Seq` 更大 → 接受；`Removed=true` 从存活表删除。
- 每次**被接受**的更新使世界版本 +1，`PlanResult.Seq` 标明结果基于
  哪个版本，便于核对“结论对应哪一帧世界”。

该规则只依赖每条消息的 Seq 与到达顺序，不依赖墙钟，因此并发交织后
的**最终状态与调度无关**：永远等于“每 ID 最大序号消息”描述的状态
（见 `TestConcurrentUpdatesNoRace` 的断言）。

### 4.3 确定性重放

- A* 邻居按固定顺序枚举；开放集在 f 相同的节点间以栅格“行优先”
  全序打破平局，与 Go map 的随机遍历顺序无关；
- 轨迹生成只用定点算术级的确定性公式（无 map 迭代、无随机数、无墙钟）；
- 时间经 `Clock` 接口注入：生产用 `WallClock`，重放用 `FakeClock`/
  `StepClock`。相同（初始位姿、地图、障碍序列、时钟）下，
  路径节点与每个轨迹点（位姿/时间/速度）逐点一致——
  `TestNavigatorDeterministicReplay` 对完整结果做了逐字段比较。

## 5. 验证方法

```bash
go test ./...                 # 全部单测
go test ./... -race -count=20 # 竞争与交织压力（推荐）
go test ./nav/ -v             # 查看每个用例打印的输入/结果/判定依据
go vet ./...
go run ./cmd/navdemo          # 端到端可解释流程演示
```

测试覆盖（每个用例日志都打印输入状态、规划结果与判定依据）：

- **全局搜索**：开阔地图成路、对角贴角、5 次重跑逐点一致、
  合围不可达、起点/目标非法、地图缺失、确定性超时（预过期 deadline）；
- **轨迹**：约束全满足 + 精确到达与末端停稳、超时部分轨迹被标记、
  超速/位姿不连续被校验器识别；
- **动态障碍与重规划**：障碍侵入旧走廊 → `Replanned=true` 且新路径
  绕开障碍、移除后恢复、合围后 `goal_unreachable`；
- **局部避障**：无障碍/窗内障碍/窗外障碍/nil 输入/身后障碍不触发、
  前方障碍触发；
- **并发**：8 writer × 25 消息与规划/读取并发（-race）、最终位置
  恒等于最大序号消息、移除消息在任意交织下不被旧消息复活；
- **配置与入口**：8 类非法配置各自得到正确分类码、端到端规划超时、
  非法障碍拒绝且不推进版本、未装地图即规划被拒绝。

## 6. 已知边界（有意为之的简化）

- 障碍模型为轴对齐矩形 + 膨胀量，栅格化以栅格为最小分辨率；
- 运动策略不做弧线路径跟随（转向与直行分离），换取约束可严格证明、
  轨迹可解释；动态代价未用于全局层，绕障完全由重规划承担；
- 目标朝向仅约束轨迹末端航向。
