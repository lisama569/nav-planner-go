# nav-planner-go

本地可复现的导航与路径规划参考实现：用本地栅格地图与圆形障碍物模拟差速驱动移动
机器人的自主导航，使**全局路径、局部避障与重规划**在各入口（`Plan` /
`ReplanningStep` / 录制重放）下给出可解释且一致的结论。

无第三方依赖，仅使用 Go 标准库。

## 能力概览

- **入口一致性**：`Plan`（一次性要完整路线）与 `ReplanningStep`（执行过程逐段
  推进）共用同一规划闭环和同一世界快照；已通过更新被接受的动态障碍在两个入口
  都会计入，成功 / 绕行 / 不可达 / 拒绝 / 预算 / 超时的结论与路线可互相解释。
- **下发前整轨迹终检**：最终交付的整条轨迹会重新对当前所有已知动态障碍与静态
  地图逐段复核；局部能绕但整条轨迹仍会撞时继续重规划或明确判失败，绝不交付
  “状态已规划、轨迹却穿障”的结果。
- **可配置规划时限**：确定性展开预算（跨机器一致、重放依赖）+ 可选墙上时钟
  时限（实时兜底，默认关闭，可注入虚拟时钟做确定性测试）；超时是独立可区分的
  `TIMEOUT` 类结论，半成品不下发。

## 目录结构

| 包 | 职责 |
| --- | --- |
| `pkg/grid` | 二维占据栅格地图，固定邻居顺序，深拷贝快照 |
| `pkg/planner` | 确定性 A* 全局搜索、展开预算 + 可选墙上时钟时限与可区分错误分类 |
| `pkg/kinematics` | 差速驱动位姿/约束模型、路径→轨迹构造、轨迹校验 |
| `pkg/local` | 确定性动态窗口法（DWA）局部避障、整条轨迹碰撞终检（`FirstCollision`） |
| `pkg/nav` | 线程安全编排器：统一规划闭环、整轨迹终检闸门、重规划、乱序更新治理 |
| `pkg/replay` | 事件录制与逐条比对的确定性重放（支持选择 `Plan` 入口，含超时结论） |
| `cmd/navdemo` | 端到端演示（正常→遇障绕行→封死不可达→非法输入→入口一致→终检→超时→重放） |

## 规划与避障策略

### 1. 全局规划：确定性 A*（`pkg/planner`）

- 四邻域移动，代价均为 1；启发式为曼哈顿距离（在四邻域网格上可采纳且一致）。
- 开放表按 `(f, 插入序号)` 排序，邻居按 **上→右→下→左** 固定顺序展开，
  因此同地图、同起终点的平局裁决完全确定，跨进程逐位复现。
- 规划时限为**双层兜底**，两者互不等价、结论可区分：
  - **展开预算** `MaxExpansions`（默认 1,000,000）：确定性的“规划时限”，
    不使用墙上时钟，超预算返回 `ErrPlanLimit` → 编排层 `PLAN_LIMIT`。
    这是跨机器、跨负载给出稳定结论与确定性重放所依赖的时限。
  - **墙上时钟时限** `DeadlineMicros`（默认关闭，`planner.NewWithLimit`
    显式开启）：只用于兜住超大/极端地图下单次搜索的最坏墙上耗时，超时返回
    `ErrPlanTimeout` → 编排层 `TIMEOUT`。时钟通过 `planner.Clock` 接口注入：
    生产用 `SystemClock`（`time.Now`，每 256 次展开检查一次以降低开销）；
    确定性测试/重放用 `ManualClock`（每次读数固定推进虚拟时间），因此
    “超时”只取决于搜索规模，不随机器负载变化。**默认构造（`planner.New`）
    不带墙上时钟，同一份输入不会因为负载不同而时好时坏。**
- 任何一种时限触发都绝不返回路径/轨迹半成品冒充成功。

失败原因使用一组彼此可区分的哨兵错误（`errors.Is` 判定）：

| 错误 | 含义 | 编排层状态 |
| --- | --- | --- |
| `ErrMapMissing` | 地图缺失 | `REJECTED` |
| `ErrStartOutOfBounds` / `ErrGoalOutOfBounds` | 起点/终点越界 | `REJECTED` |
| `ErrStartOccupied` / `ErrGoalOccupied` | 起点/终点落在障碍上 | `REJECTED`（重规划中起点被封为 `BLOCKED`） |
| `ErrUnreachable` | 开放表耗尽仍到不了目标 | `UNREACHABLE` |
| `ErrPlanLimit` | 超出确定性展开预算 | `PLAN_LIMIT` |
| `ErrPlanTimeout` | 超出墙上时钟时限 | `TIMEOUT` |

### 2. 轨迹构造与约束模型（`pkg/kinematics`）

机器人为差速驱动：指令是体坐标系 `(V, Omega)`，单段运动学按圆弧/直线
**精确积分**（`Integrate`）。栅格 `(x,y)` 的中心映射到世界坐标 `(x, y)`。

默认约束（`DefaultConstraints`）：

- 线速度 `0 ≤ V ≤ 1.0` 栅格/秒；
- 角速度 `|Omega| ≤ π/2` 弧度/秒；
- 曲率约束（仅行进段）`|Omega/V| ≤ 1.0`（1/栅格），保证最小转弯半径；
- 单段转角变化 `|Δθ| ≤ π/2`，角度差按最短方向包裹到 `[-π, π]`；
- 每段 `DT > 0`；
- **位姿连续**：每段必须能用其 `(V, Omega, DT)` 精确积分到下一个采样点
  （容差 `1e-7`），否则记 `ViolationDiscontinuity`。

`PathToTrajectory` 按构造即合法：每条网格边先“原地分段转向”（`V=0`、
`|Omega|=MaxOmega`、每段转角不超过 `MaxDTheta`），再以 `MaxV` 匀速直行，
末段精确落在下一个单元格中心。`nav` 层在下发前仍会调用 `Validate` 二次复核；
任何违规结论为 `StatusConstraintViolation`（`ErrConstraintViolation`），
违规轨迹**不会被当作有效结果下发**。

违规分类：`ViolationVelocity / ViolationAngularVelocity / ViolationCurvature
/ ViolationTurnAngle / ViolationDiscontinuity / ViolationTiming`，
每条违规带段号与可读信息。

### 3. 局部避障：确定性 DWA（`pkg/local`）

- 在动态窗口内**确定性枚举** `(V, Omega)`：线速度从高到低、角速度从
  `-OmegaMax` 到 `+OmegaMax`（对称采样），固定枚举顺序就是固定平局裁决。
- `OmegaMax` 同时受 `MaxOmega` 与 `MaxDTheta/DT` 收紧；行进段还要满足曲率上限。
- 候选指令用差速运动学精确前滚 `Horizon` 步，任一点进入圆形障碍
  （半径 + `ObstacleMargin` 安全裕度）或越界/占据栅格即淘汰。
- 采用**胡萝卜点跟随**：沿全局路径在前视半径内选最远可达的路径单元格作为
  瞄准点（前视半径至少一个栅格），避免斜切墙角与原地摇摆。
- 评分 = 末端到目标距离 + 朝向偏差权重 − 间隙裕度权重，仅在严格更优时替换，
  保证平局可复现。停车指令 `(0,0)` 不参与寻优，防止“原地不动”被误判为最优
  而永久停滞；原地转向 `(0, Omega≠0)` 保留用于对正。
- 除停车外没有任何合法候选时返回 `blocked=true`，由编排层触发重规划。

### 4. 统一规划闭环（`nav.Plan` / `nav.ReplanningStep`）

两个入口共用**同一条**确定性闭环和同一份世界快照（原始静态地图 + 全部已通过
更新被接受的动态障碍），因此对同一时刻的世界给出可互相解释的结论：

1. 在工作地图上全局 A* → 构造轨迹 → 运动学约束校验；
2. **整轨迹终检闸门（两个入口共有）**：对“准备下发的整条轨迹”逐段重新检查
   原始静态地图与当前所有圆形动态障碍（检测口径与 DWA 完全一致：半径 +
   `ObstacleMargin`、采样点所在栅格）。终检覆盖整条轨迹，而不只是局部试探的
   那一小段；发现冲突（首碰点带段号、位姿、侵入量写入诊断）就把障碍足迹
   （含安全裕度、碰撞点所在格，按 `(Y,X)` 排序去重）确定性膨胀进工作地图，
   回到第 1 步继续重规划；
3. **逐步入口额外闸门**：`ReplanningStep` 在终检通过后再用 DWA 沿路径短步
   推进做“可执行性”验证，局部窗口被堵同样触发第 2 步的膨胀重规划；
   `Plan` 不跑这一步，但因为终检闸门在前，两者对障碍的结论与路线一致；
4. 成功时若发生过绕行，状态为 `REPLANNED`（否则 `PLANNED`）；
   重规划后目标不可达为 `UNREACHABLE`（保留既有兼容语义）；
   预算耗尽为 `PLAN_LIMIT`；墙上时钟超时为 `TIMEOUT`；
   机器人被封死（起点被包围），或用尽重规划次数后“搜索仍给得出格中心路径、
   但终检始终碰撞”（纵深防御，防御规划/构造输出漂移）为 `BLOCKED`
   （`ErrTrajectoryCollision`）。任何失败分类都不会携带可下发的半成品
   路径/轨迹，因此**不可能出现状态显示已规划、轨迹却穿过已知障碍的情况**。

> 边界说明：膨胀采用保守的格中心足迹（圆覆盖到的格整体禁行），因此多数
> “擦碰”冲突在重搜时直接表现为不可达；`BLOCKED + ErrTrajectoryCollision`
> 是留给终检的最后防线，测试用一个确定性的规划器接缝（`Navigator` 未导出
> 字段，生产恒为 nil）直接驱动验证。


## 并发模型与确定性保证

- `Navigator` 用一把 `sync.RWMutex` 保护地图、障碍物表与序号水位；
  CPU 密集的规划在锁外基于**深拷贝快照**执行，既不阻塞传感器更新，
  也保证一次规划看到的是一致状态（`go test -race` 验证无数据竞争）。
- **乱序/陈旧更新规则**：
  - 地图更新按全局 `Seq` 单调，落后水位的更新被拒绝并返回
    `nav.ErrStaleUpdate`；`nil` 地图返回 `ErrInvalidUpdate`。
  - 障碍物更新按 `(障碍物ID, Seq)` 每 ID 独立水位判定：同一 ID 的旧观测被丢弃，
    不同 ID 的消息之间不要求全局排序——多个传感器可并发写不同 ID。
- `Snapshot()` 返回深拷贝地图与**按 ID 排序**的障碍物切片，保证读结果确定。
- 确定性来源：无 goroutine 参与决策、无 map 遍历顺序泄漏、
  固定枚举/展开/排序规则、浮点运算顺序固定。相同初始位姿、地图与障碍物
  序列在任意时间重放都得到逐位相同的路径与轨迹。
- **时钟的确定性边界**：墙上时钟时限默认关闭，因此默认流水线完全不接触
  `time.Now`。开启墙上时钟时限时，生产环境的 `TIMEOUT` 触发点天然受负载影响
  （它是实时兜底，不参与复现承诺）；需要确定性的测试与重放改用
  `planner.ManualClock`，其“超时”只由搜索展开数决定，可逐位复现。展开预算
  `PLAN_LIMIT` 在任何配置下都是确定性的。
- `pkg/replay` 把事件（地图/障碍物/请求，按逻辑 Tick 排序）与结论录制成日志，
  可用全新 `Navigator` 重放并逐字段（状态、错误原因、重规划次数、路径、
  每个轨迹点）比对；比较采用**精确相等**而非近似，避免容差掩盖真实的不确定性。

## 验证方法

```bash
# 构建
go build ./...

# 全部单测（带竞态检测；测试日志打印输入状态、规划结果与判定依据）
go test -race -count=1 -v ./...

# 端到端演示
go run ./cmd/navdemo
```

测试覆盖的关键场景：

- **动态障碍**：障碍堵住近路缺口 → 终检/DWA 判定冲突 → 障碍膨胀 → 重规划走低路
  （`REPLANNED`，路径不再经过被堵缺口）；
- **入口一致**：无障世界、障碍堵近路、两缺口全封三种世界下，`Plan` 与
  `ReplanningStep` 的状态、错误分类与路径逐格一致，且成功结论的轨迹都通过
  整轨迹终检；非法输入（越界/占据）在两个入口同样被一致拒绝；
- **整轨迹终检**：构造“路径格中心全自由、但直行段侵入圆形障碍安全裕度”的
  擦碰场景——可绕行时终检驱动重规划，交付逐段无碰的绕行轨迹；走廊被封死时
  明确 `UNREACHABLE`；用确定性桩件模拟规划器漂移输出时，终检闸门在重规划
  预算耗尽后判 `BLOCKED + ErrTrajectoryCollision`，且不下发半成品；
- **规划时限**：虚拟时钟超时给出独立 `TIMEOUT`（与 `PLAN_LIMIT` 不混淆、
  无半成品），触发点跨运行稳定；`DeadlineMicros=0` 时行为与普通规划完全一致；
  既有“展开 1 个节点即 `PLAN_LIMIT`”用例不回归；
- **不可达目标**：两个缺口都被封死后 `UNREACHABLE` + `planner.ErrUnreachable`；
- **非法输入可区分**：目标越界、目标占据、起点占据、地图缺失、预算耗尽
  分别给出不同哨兵错误与状态分类；
- **约束违规**：超速、超角速度、超曲率、超转角、位姿不连续、非正 `DT`、
  空轨迹均被 `Validate` 标记；
- **并发更新**：多传感器并发写 + 并发快照/规划 + 并发乱序注入，`-race` 无报警、
  快照一致、乱序全部按水位拒绝；
- **确定性**：同输入多次运行结果逐位相同；录制/重放一致（含一次性入口与
  `TIMEOUT` 结论），且能检测出地图被篡改导致的分叉。

所有测试日志均打印输入状态（起点、目标、地图/障碍）、规划结论（状态、哨兵
原因、重规划次数、展开节点数、路径与轨迹规模）与判定依据（走哪个缺口、
首碰点段号与侵入量、超时触发展开数等），便于复盘。

## 兼容性说明

以下老用法的行为保持不变：

- `planner.New(maxExpansions)` 签名与语义不变；默认仍为 1,000,000 展开预算，
  墙上时钟时限**默认关闭**，旧调用方不会得到任何 `TIMEOUT`。
- `nav.New` / `ApplyMap` / `ApplyObstacle` / `Snapshot` 接口与乱序水位规则不变。
- 无动态障碍时，`Plan` 与 `ReplanningStep` 的结论与旧版逐位一致（终检对
  纯静态地图等价于原先的构造 + `Validate` 复核，不会新增绕行）。
- 状态分类中既有的 `PLANNED/REPLANNED/REJECTED/UNREACHABLE/PLAN_LIMIT/
  CONSTRAINT_VIOLATION/BLOCKED` 语义保留；`TIMEOUT` 为新增枚举值（数值追加，
  不改变既有状态的数值映射）。`replay.Event` 新增 `OneShot` 字段，零值
  （false）保持原来走 `ReplanningStep` 的行为。
- 行为差异（有意的修复）：旧版一次性 `Plan` **不看动态障碍**，可能给出穿过
  已接受障碍的路线；新版两个入口统一计入动态障碍并过终检，这是本次要消除的
  不一致，不视为兼容性回归。
